## 2. Slot Hub 定位

### `DECIDED` 核心定位

> Slot Hub 是以結構化遊戲資料為核心，幫助繁體中文使用者查找、篩選、比較並看懂老虎機遊戲的平台。

產品由五個互相連結的部分構成：

- 遊戲資料庫
- 搜尋與探索
- 比較工具
- 知識解釋
- 來源與核對資訊

### `DECIDED` 長期方向

- 長期定位是「廣泛而可靠的遊戲資料庫」。
- 遊戲依搜尋需求與結構價值排序，採分批方式擴充。
- Slot Hub 不是只收少數精選遊戲的編輯名單。
- Slot Hub 也不是在未驗證身份、資料及來源前大量灌入遊戲的目錄。
- 台灣搜尋需求是收錄與驗證的優先順序依據，不是所有遊戲的發布硬門檻。
- 所有未知、未核對或來源衝突的資料應保留缺值或差異，不為了完整率自行補造。

## 3. 網站範圍與邊界

### `DECIDED` 核心範圍

- 老虎機是網站核心。
- Slot Hub 不提供遊戲、下注或結果預測服務。
- 沒有可靠真實數據前，不建立熱門排行、最好贏、勝率排行或獲利預測。

現有捕魚機入口與基礎教學可以保留。目前尚無捕魚機遊戲資料，也沒有足以支援捕魚機探索的專屬資料模型。

等待專屬資料模型與真實遊戲資料成熟後，再評估捕魚機遊戲收錄、探索器與內容擴充。現階段不擴大。

### `DEFERRED` 輪盤

輪盤只屬程式中的保留方向，不代表已決定建立入口、內容或資料模型。

### `DO_NOT_BUILD_YET` 排行與預測

- 熱門排行
- 最好贏或勝率排行
- 投注建議
- 獲利或結果預測

上述能力不得在沒有可靠資料定義、來源與產品決策前自行實作。

## 4. 核心使用者需求

### `DECIDED`

Slot Hub 應服務下列七種核心需求：

1. 已知道遊戲名稱，直接查資料。
2. 不知道遊戲名稱，依條件找遊戲。
3. 挑出幾款遊戲，想比較差異。
4. 看過一款遊戲，想找同系列、同廠商或相似遊戲。
5. 看不懂 RTP、波動度、賠付機制或 Feature。
6. 想了解廠商、系列或玩法。
7. 想確認資料來源與可靠性。

## 5. 三條核心使用流程

### 5.1 `CURRENT` 搜尋／探索到遊戲資料

遊戲庫搜尋／探索 → 單款遊戲資料頁。

目前已具備主要功能，包括遊戲名稱搜尋、部分結構化篩選、遊戲卡與單款遊戲頁。後續新增條件仍須另案批准。

### 5.2 `CURRENT` 遊戲資料到比較

單款遊戲資料頁 → 加入比較 → 最多三款並排比較。

目前已具備加入、移除、URL 分享與本機狀態保存等主要功能。比較的角色是呈現已有資料差異，不替使用者判定哪款一定比較好。

### 5.3 `DECIDED` 知識到遊戲再到比較

知識內容 → 符合概念的遊戲 → 單款資料 → 比較。

這是已定案的產品方向；目前已有知識文章與部分人工入口，但 Guide、概念與 Game 的正式雙向關聯尚未實作。

## 7. 核心內容實體與角色

### 7.1 Game

#### `CURRENT`

Game 是核心實體。搜尋、篩選、比較、廠商關聯與其他遊戲關聯，應讀取同一套遊戲資料，避免各頁形成互相矛盾的獨立事實。

### 7.2 Provider

#### `CURRENT`

Provider 是獨立實體，現有廠商總覽與廠商頁可作永久 Hub／頁面。Provider 可承載名稱、角色、別名、品牌與市場等資料，但只有已核對內容才應對外呈現。

### 7.3 Series

#### `CURRENT－LIMITED`

目前 Game 內已有系列識別、系列名稱、代數與相關遊戲等基礎欄位，也已有少量遊戲使用。此複合標記表示能力目前存在但範圍有限，不新增一種治理狀態。

#### `DECIDED` 關係分類

必須分開判斷：

- 官方系列：官方或可靠來源明確確認的系列、續作或代數關係。
- 品牌／角色宇宙：共享角色、品牌、世界觀或 IP，但不必然是正式續作。
- 相似遊戲：因題材、名稱、玩法或 Feature 相似而可供探索，但不是正式系列。

只有官方或可靠來源明確確認系列或續作時，才填正式系列關係。共同角色、品牌、題材、名稱或玩法相似，不得自行宣稱為正式系列或代數。

#### `DEFERRED`

- 獨立 Series 實體
- Series Collection
- 系列永久頁

是否建立須等待系列數量、資料關係、搜尋需求及獨立內容價值成熟。

### 7.4 Mechanism

#### `DECIDED` 定義

> Mechanism 指一般中獎組合依什麼規則成立。

現有或待驗證的概念包括：

- Paylines
- Ways to Win
- Megaways
- Cluster Pays
- Scatter Pays
- Pay Anywhere 或其他特殊原廠機制

Scatter symbol 是 Feature／符號概念，不等於 Scatter Pays。特殊原廠名稱不能在未確認實際規則前強塞進既有分類；無法可靠正規化時，先保留原廠文字。

### 7.5 Feature

#### `DECIDED` 定義

> Feature 指遊戲具備哪些可觸發、改變玩法或影響回合的功能。

例如：

- Free Spins
- Wild
- Scatter
- Multiplier
- Cascading
- Hold & Spin
- Bonus Buy
- Jackpot Feature

Mechanism 與 Feature 不得因名稱相似而混為一談。

新原廠詞彙第一次出現時，先保留原文。只有在跨遊戲重複、定義穩定，且對搜尋、篩選、比較或教學有實際價值時，才提議升級為共用結構化 Feature。提議本身仍不構成 Schema 或 taxonomy 修改授權。

### 7.6 Guide

#### `CURRENT`

Guide 是獨立內容實體，現有分類、文章頁與教學總覽可承載概念解釋。

#### `DECIDED` 方向

- 教學負責解釋概念。
- 教學可顯示少量代表遊戲。
- 教學應能導向已套用條件的完整探索結果。
- 遊戲頁未來可以反向顯示相關教學。

#### `DEFERRED`

正式的 Guide 與 Game／Mechanism／Feature 雙向關聯欄位及實作，等待內容量與關聯規則成熟後再決定。

## 8. 搜尋、篩選與比較的角色

### 8.1 搜尋

#### `CURRENT`

搜尋目前涵蓋：

- 遊戲正式名稱
- 繁中名稱
- 原文名稱
- aliases
- 廠商
- 教學內容

搜尋用於「知道或記得某些文字」時直接找到實體或內容；搜尋不是結構化篩選的替代品。

### 8.2 篩選

#### `CURRENT`

現有遊戲探索器提供：

- 廠商
- 主類型（資料中存在多種主類型時才顯示）
- 子類型
- 最低 RTP 的既定門檻
- 波動度

目前沒有使用者可選的排序功能，也沒有 Feature、Mechanism、系列、最高倍數、Bonus Buy 或發行年份篩選。

#### `DECIDED` 產品方向

篩選負責可核對的結構化條件。未來可評估的條件包括：

- 廠商
- RTP
- 波動度
- 最高倍數
- Mechanism
- Feature
- Bonus Buy
- 系列
- 發行年份

此處只定義產品方向，不表示所有條件已核准實作。具體欄位、互動、URL 狀態與效能承接方式須另案評估。

### 8.3 比較

#### `CURRENT`

- 比較是使用工具。
- 目前最多三款。
- 目前比較廠商、RTP、波動度、盤面、Paylines／Ways 文字及 Bonus features 等已有資料。
- 缺值保持為缺值，不為填滿比較表而補造資料。
- 比較選擇可由 URL 與本機狀態保存。

#### `DECIDED`

- 比較不武斷選出哪款遊戲一定比較好。
- 比較結果不建立大量 SEO 頁面。
- 新比較欄位只有在資料定義與取得率足夠時才應評估；本藍圖不直接授權新增。

## 10. 教學與機制搜尋意圖

### `DECIDED`

- 同一概念只設一個主要搜尋入口。
- 優先考慮「概念解釋＋代表遊戲＋完整探索入口」的混合型內容。
- 例如 Megaways 的主要入口可以同時解釋概念並帶出相關遊戲，而不是建立多個互相競爭的薄頁。
- 目前不先決定未來一定使用 `/guide/` 或新的 Mechanism URL。
- 在搜尋需求、相關遊戲數量與內容價值成熟前，不建立機制集合頁。

### `DEFERRED`

- Mechanism 主要入口的 URL
- Mechanism 的最終頁型
- 教學頁與機制集合頁的 canonical／主從關係

## 11. 遊戲收錄策略

### `DECIDED` 評估面向

遊戲選擇使用以下五個面向：

- 搜尋需求
- 官方資料完整度
- taxonomy／結構補位價值
- 系列與內部連結價值
- 廠商代表性

不得記錄或使用虛構搜尋量、推測流量或無法追溯的熱門程度。

### `DECIDED` 收錄原則

- 搜尋需求高的遊戲優先。
- 能補足廠商、系列、Mechanism 或 Feature 結構的遊戲也可收錄。
- 不平均分配每家廠商的遊戲數量。
- 不只收最新遊戲。
- 不因系列存在就一次收完整系列。
- 不依娛樂城大廳排序直接認定熱門。
- 身份與來源無法確認時維持候選，不建立正式遊戲資料。
- 台灣搜尋需求影響優先順序，但不是發布的唯一門檻。

## 12. 候選、可建立草稿與可發布

### 12.1 `CANDIDATE`

- 只是待驗證名單。
- 可以替換、淘汰或延後。
- 不直接進入 Game Collection。
- 不代表繁中名稱、圖片、系列、資料或發布已核准。

### 12.2 `DECIDED` 可建立草稿門檻

至少需要：

- 正式遊戲身份
- 正式英文名稱
- 開發商
- 不重複的穩定 slug
- 至少一個可接受來源
- 與現有遊戲完成重複比對

系列、Mechanism 或 Feature 無法證明時，可以留空或保留原廠用語，不能猜測。

### 12.3 `DECIDED` 可發布門檻

至少需要：

- 通過草稿門檻
- 可公開的名稱與摘要
- 正確廠商連接
- 足以形成獨立資料價值的已核對內容
- 資料來源與核對日期
- 沒有未解決的身份或重大數據衝突
- 可靠且可追溯的官方或授權圖片
- 頁面不會只剩名稱與大量空欄

缺少投注上下限、Game ID、發行日期、Jackpot 類型或多版本 RTP，不必永久阻止發布。第一階段無可靠圖片的遊戲可以建立草稿，但暫不發布。

## 13. 來源原則

### 13.1 `DECIDED` 文字資料來源優先順序

1. 廠商官方遊戲頁、規則頁、正式文件、官方遊戲目錄或官方開發資料。
2. 官方新聞稿與正式合作發行資料。
3. 官方授權合作方或聚合平台；可以補官方缺值，但必須清楚標示來源。
4. 有編輯責任的產業資料庫或媒體；只作交叉核對。
5. 一般娛樂城、聯盟網站、轉載站；只作線索。
6. 搜尋摘要、AI 回答、無來源文章及社群轉述；不能作正式事實來源。

RTP、最高倍數、投注範圍等精確數值優先要求官方來源。來源有差異時保留差異、版本與來源，不自行選擇看起來最合理的數字。

### 13.2 `DECIDED` 圖片來源

優先使用：

- 官方遊戲頁
- 官方 media kit／press kit
- 官方 CDN
- 官方新聞稿素材
- 權利與來源清楚的官方授權合作方素材

不使用：

- Google 圖片搜尋結果本身
- 來源不明下載
- 其他網站浮水印圖片
- AI 仿製官方遊戲 Logo 或作品圖

圖片資料至少保存：

- 原始來源 URL
- 取得日期
- 是否為官方素材
- 裁切或轉檔說明
