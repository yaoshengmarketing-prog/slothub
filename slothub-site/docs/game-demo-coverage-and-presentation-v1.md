# Game Demo 覆蓋與呈現規則 v1

狀態：APPROVED WORKING RULE

## 目的

Slot Hub 將試玩／遊戲入口視為遊戲資料的一部分：讓讀者在理解名稱、玩法、版本與來源後，能前往正確的官方測試頁；官方缺少精確入口時，也可前往已核對的第三方平台同款頁。入口不是娛樂城導流，也不使用「立即玩」「試手氣」或獲利暗示。

## 三層入口責任：Provider 必備，Demo 另行核對

後續 Agent 處理任何一款遊戲時，必須把以下三件事分開，不得互相代替：

1. 每款 published Game 都必須對應一個既有的站內 Provider record，前台因此一定能連到 Slot Hub 的廠商頁；沒有可確認的廠商身份時，該 Game 不應發布。
2. 每個 published Provider 都必須保存可追溯的 `officialUrl`，Game detail 一定保留「廠商官網」入口。這只證明廠商身份及官方網站，不等於該款遊戲的 Demo。
3. 單款 Demo／官方遊戲頁／第三方同款頁是額外的可選資料。只有核實到精確單款目的地時才加入；目前找不到時保留 `not-verified` 或其他真實狀態，但站內廠商頁與廠商官網仍照常顯示。

因此，Agent 的固定順序是：先核對 Game → Provider 身份，再核對 Provider 官方網站，最後獨立查找單款 Demo。不得以「有廠商官網」推論「有 Demo」，也不得因 Demo 缺失而省略或改寫廠商資訊。

## 每款遊戲必須保存的狀態

- `available`：已核對可對到該款遊戲的精確官方 Demo、官方遊戲頁或清楚標示的第三方平台同款頁。
- `login-required`：入口存在，但目前需要廠商登入。
- `access-restricted`：核對時受到權限或存取限制。
- `not-verified`：目前未核實精確入口；不等於廠商沒有 Demo。
- `checkedAt` 只在實際核對該款遊戲的 Demo 後更新。目錄仍存在、排程跑過或首頁可開啟都不算重新核對。

## 來源與去重規則

1. 優先使用廠商官方遊戲頁、官方 Demo、官方 Help／Client Hub；官方缺少精確入口時，才使用可核對的第三方平台同款頁。
2. 第三方平台頁必須同時看得到單款遊戲名稱與 Provider／Studio 身份，保存平台名稱、核對日期及同款證據，前台不得稱為官方。
3. 連結必須能辨認單款遊戲。Demo 大廳、搜尋結果、通用登入頁、同一網址對應多款遊戲、聯盟轉址、娛樂城促銷頁或只談遊戲的文章，只能保留為待查線索。
4. 不從搜尋摘要直接建立公開入口；搜尋結果只作發現線索，必須實際開啟目的頁核對。
5. 中文名、英文名、別名與 Game ID 先對照現有 Game record，避免重複或把入口掛錯遊戲。
6. 找不到、衝突或遭阻擋時記錄狀態並繼續其他遊戲；入口缺值不阻擋遊戲發布。

## 只使用清楚標示的站外連結

- `direct-demo` 是官方可直接啟動的測試內容；`official-game-page` 是含 Demo 入口的官方遊戲資料頁；`platform-game-page` 是經人工核對名稱與 Provider 的第三方平台同款頁。
- 所有入口一律以站外連結呈現；Slot Hub 不嵌入第三方 Demo，也不把廠商產品頁誤稱為站內可玩 Demo。
- `direct-demo` 的按鈕明確標示「前往官方 Demo 頁」；`official-game-page` 則標示「前往官方遊戲頁」。
- `platform-game-page` 明確標示平台名稱、第三方身份與「前往平台遊戲頁」，不保證該頁一定免登入或在所有地區提供免費 Demo。
- 歷史瀏覽器測試可以保留為核對證據，但不得再改變公開呈現方式。

## 前台呈現

- Game detail 同時保留三種不同責任的入口，不得互相取代：
  1. 「廠商資料」指向 Slot Hub 站內 Provider Hub，承接本站整理的廠商身份與已收錄遊戲。
  2. 「廠商官網」使用 Provider record 已保存的 `officialUrl`，只代表廠商官方網站，不得當成單款 Demo 或單款遊戲資料證據。
  3. 「官方 Demo／官方遊戲頁／同款遊戲平台頁」必須指向該款遊戲的精確入口；第三方平台頁不得冒充廠商官網或官方 Demo。
- 即使尚未核實單款 Demo，仍應保留「廠商資料」與「廠商官網」；反之，找到第三方同款頁也不能移除或取代這兩個廠商入口。
- `direct-demo + external`：在「快速看懂」後顯示正式的「官方 Demo」資料模組，列出廠商身份、入口類型、核對日期及精確官方連結。
- `official-game-page + external`：同一位置顯示已核實官方遊戲頁與新分頁按鈕。
- `platform-game-page + external`：同一位置顯示「同款遊戲平台頁」、平台名稱、非官方說明及新分頁按鈕。
- 其他狀態：完整資料顯示可理解的狀態文字，不輸出 disabled 按鈕或假連結。
- 不以 Demo 是否存在作推薦、排名或遊戲品質判斷。

## 每日新增與每月回查

每日收集每處理一款遊戲，都要順便核對 Demo 並寫回同一個 Game record；失敗只重試未完成項目。每月回查只在實際開啟並核對精確入口後更新日期。兩者皆沿用既有保存、驗證、Commit、Push 與 Preview 流程，不建立第二套資料 owner。

後續 Agent 每次處理單款遊戲時，依序檢查並分開保存：站內 Provider Hub 對應、Provider `officialUrl`、以及該款遊戲的精確 Demo／遊戲頁。不得用 Provider 首頁補 Demo 缺值，也不得用平台同款頁改寫 Provider 官方網址。

## 本次全量基線

2026-09-19 以當時 257 款 published Games、199 家 Provider 及 546 個已保存來源頁完成一次覆蓋盤點。盤點輸出保存在 `data/game-demo-coverage.json`；Game frontmatter 是公開呈現的資料 owner，報告只作可重跑的營運 QA 與接續清單。

2026-09-19 完成第三輪未完成入口深挖及 565 個來源／目的地的全量連線重驗後，共有 214 個可用入口：53 個官方直達 Demo、147 個官方遊戲頁及 14 個明確標示的同款平台頁；另有 41 個 `not-verified` 與 2 個 `access-restricted` 待接續。這一輪新增核實 38 款；另有 4 筆雖已找到精確候選，但因本次連線失敗或 HTTP 403 仍保留為未核實／受限，沒有勉強發布。`data/game-demo-manual-review.json` 保存人工／瀏覽器覆核決策，其餘官方入口由來源頁與精確 URL 稽核建立；不得把可用入口總數誤稱為全部都有獨立人工覆核紀錄。所有入口均使用站外連結，日後 Agent 只針對未完成、新增或明確需重新核對的遊戲接續，不得重新啟用 iframe。
