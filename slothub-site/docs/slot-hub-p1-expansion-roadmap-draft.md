# Slot Hub P1 擴充步驟藍圖

文件狀態：`APPROVED FOR P1 EXECUTION`

執行狀態：三步依本藍圖連續完成；最終結果以同批完整 CI 與 Cloudflare Pages Preview 線上回讀為準。

最高依據：`docs/slot-hub-master-blueprint-v3.md`

執行原則：依下列順序一次只做一步，前一步完成設計、施工與驗證後才開始下一步；不再為既定範圍逐步停等人工核准。只有成果會因此錯誤、現有資料無法誠實承接，或必須擴張 Schema、taxonomy、永久 URL 規則及其他既定範圍時才停止回報。

## 第 1 步：多路贏法代表頁

### 使用者能得到什麼

理解多路贏法如何成立、它與賠線及 Megaways 的差異，並能前往現有遊戲庫查看已被正式分類為多路贏法的遊戲。

### 頁面要呈現什麼

- 多路贏法的清楚定義、判讀方式與資料限制。
- 與賠線、Megaways 的必要邊界，不把名稱相近的機制視為相同。
- 少量有第一方資料支持的代表遊戲案例。
- 連往既有賠付機制 Guide、相關 Game detail，以及精確 `/games/?mechanism=ways-to-win` 的普通連結。

### 哪些事情不做

- 不一次建立其他 Mechanism 子頁或大量薄頁。
- 不修改 taxonomy、Schema、Explorer URL 或既有遊戲分類。
- 不建立玩法排名、推薦分數或「比較容易贏」的暗示。

### 做到什麼算完成

代表頁具備獨立且完整的搜尋與閱讀價值；定義、案例及連結均有資料依據；桌機、手機、無 JavaScript、內部連結及 Preview safeguards 通過，並完成本輪授權下的內容與產品驗收。

## 第 2 步：最近核對的遊戲資料

### 使用者能得到什麼

辨認哪些遊戲資料最近完成核對，並理解「最近核對」代表資料維護時間，不代表新遊戲、熱門、完整無缺或品質排名。

### 頁面要呈現什麼

- 使用既有最後核對日期產生的最近核對遊戲入口。
- 遊戲名稱、Provider、核對日期及前往 Game detail 的普通連結。
- 簡短說明核對日期、來源與缺值應如何閱讀。
- 資料量不足或日期缺失時的誠實空狀態。

### 哪些事情不做

- 不新增資料庫、CMS、更新分數、熱門榜或自動品質評級。
- 不把缺值補成已核實，也不把最近核對說成資料全部完整。
- 不建立任意日期 query 的可索引薄頁或改變 Game detail 的資料 owner。

### 做到什麼算完成

入口完全由既有 published Game 與核對日期產生，排序固定且可重現；缺值與日期語意清楚；所有結果可回到 Game detail，並通過資料、UI、手機、無 JavaScript 與本輪產品驗收。

## 第 3 步：賠付表與投注風險教學

### 使用者能得到什麼

知道如何從原廠賠付表辨認符號、組合、投注基準與成立條件，並理解投注額、RTP、結果機率與短期輸贏之間不能互相替代；不把讀表轉化為獲利保證或下一次結果預測。

### 頁面要呈現什麼

- 賠付表的基本閱讀順序，以及符號賠付、組合條件、Feature 規則與主要賠付機制的邊界。
- 只使用可追溯第一方資料的少量案例。
- 提高投注額不代表提高 RTP、改變中獎機率或保證回收的風險教育。
- 追損、投注排列與短期結果不能改變遊戲既定機率的必要說明。
- 連往賠付機制 Guide、相關 Game detail 與精確 Explorer 條件的普通連結。
- 只在需要釐清 Feature 購買入口與賠付表責任時，簡短說明邊界並連回既有 `/guide/slot-bonus-buy-explained/`；不在新頁重複 Bonus Buy 的成本、投注基準、版本或市場差異。

### 哪些事情不做

- 不提供個人化下注金額、回本方法、追損策略、致勝公式或遊戲排行。
- 不把不同原廠的 `stake`、`bet amount`、`total bet` 等投注與賠付基準自行統一。
- 不建立第二篇 Bonus Buy 教學，也不移交或新增 `bonus-buy` relationship owner。
- 不修改 Game data、Schema、taxonomy、relationship owner 或 Explorer 規則。
- 不因現有 Diagram 系統可用就強制加入圖解。

### 做到什麼算完成

內容能讓一般使用者正確閱讀賠付表與投注風險，同時維持既有 Bonus Buy Guide 及其他專門 Guide 的責任邊界；所有精確案例均有可達的第一方來源；新頁不產生重複 owner 或競爭入口，且內容、關聯、站內連結、桌機與手機閱讀、無 JavaScript 及 Preview safeguards 通過，並完成本輪授權下的內容與產品驗收。

## 固定停止規則

- 第 1 步完成設計、施工與驗證後，自動開始第 2 步；第 2 步通過相同門檻後，自動開始第 3 步。
- 三步全部完成後，統一執行整站 Preview 回歸、Commit、Push、Cloudflare Pages Preview 部署與線上回讀。
- 只在成果會錯誤、確實無法繼續，或需要超出本藍圖既定範圍時停止；一般工程細節不另設人工停等。
- 第 3 步完成後不得新增第四步，也不得自動開始其他 P1、P2、外部全量資料蒐集或匯入工作。
- 本藍圖不授權正式網域、DNS、Wix、301、migration 或正式索引切換。
